# MBON Dashboard

An exploratory dashboard for the Marine Biodiversity Observation Network
metagenomics data: browse projects, collections, samples, sequencing runs,
Kraken2 / Wilderlab taxonomic results, and **find ocean mammal & fish species in
an area matching environmental conditions** (depth, salinity, temperature…).

## Architecture

```
api/                 Flask REST API
  app.py             routes (schema endpoints + connections + explore)
  datasources.py     data-source adapters: Postgres, .xlsx, Google Sheets
  connections.py     server-side connection registry (secrets never leave the host)
  tests/             pytest for the spreadsheet adapter + Explore cross-filter
frontend/            no-build static frontend (Vue 3 + D3 + Leaflet via CDN)
  metadata.html      standalone comparison page with demo data (no API needed)
  components/        Sunburst.vue — standalone Vue SFC (not wired into index.html)
  index.html         markup only
  css/app.css        styles (split out of index.html)
  css/enhance.css    styles for the universal table/chart tools
  js/app.js          application + chart helpers (split out of index.html)
  js/enhance.js      universal export / column-edit / sort layer (loads after app.js)
  config.js          generated by make-config.sh (git-ignored); see config.example.js
```

## Data sources (Sources tab)

The dashboard is no longer hard-wired to one database. The **Sources** tab lets
trusted analysts register and switch between data sources at runtime:

- **Postgres** — the canonical MBON schema (all dashboard views).
- **Excel (.xlsx)** — a workbook on the server. A *samples* sheet (lat/lon +
  environmental columns) and an *observations* sheet (species + read counts) are
  auto-detected and joined by sample name.
- **Google Sheets** — a link-shared / published sheet, read via its CSV export.

Connection secrets (e.g. a Postgres password) are stored server-side in
`api/connections.json` and are **never** returned to the browser. Raw SQL is not
exposed; Explore uses parameterized queries / pandas filtering only.

`api/connections.json` is created on first run (seeded from the `PG*` env vars)
and is git-ignored.

## Import panel (browser-side file import)

A floating, resizable **Import** side-panel lets analysts load data without a
server path. It lives in both `frontend/index.html` (the modular dashboard, via
`js/import-panel.js` + `css/import-panel.css`) and the self-contained
`metadata.html` (same module, inlined). Key features:

- **Multi-file** drag-and-drop or file-picker for `.xlsx / .xlsm / .csv / .tsv`.
- **Resizable** by dragging the panel's left border; collapses to a launcher tab.
- **Regex** filter bar over source names, columns, and row values.
- **Mapping / validation popup** per file. For a workbook (e.g.
  `MBON_Sample_Tracker.xlsx`) each tab is auto-matched to a role
  (Samples, Cruise, Runs, Bioinformatics, Wilder Results, Kraken2, TaxTriage).
  Header rows are **detected**, not hard-coded, so banner/description rows above
  the header are skipped. The role and the dataset name are both **editable**,
  and validation explains *why* a tab is or isn't an acceptable fit (matched vs.
  missing columns). Junk tabs (drop-down lists, validation sheets) default to
  *Ignore*.
- **Raw CSV** (e.g. `The Wilderness.csv`, a stripped Wilder export) is imported
  as Wilder Results keyed only by **Sample ID**. You choose to keep the samples
  **standalone (dissociated)** or **associate** them with a cruise — and can flip
  that link later from the source card without re-importing.
- **Accumulating, toggleable sources** — multiple files coexist; toggle any
  source on/off, rename, or remove it.

In the modular dashboard, committed sources are POSTed to a small, DB-independent
store (`POST/GET/DELETE /api/import`, persisted to `api/imports.json`) and shown
in the **📥 Imports** view. In `metadata.html` the same imports feed every local
view, chart, and the map directly.

## Explore tab

The Explore tab is the exploratory species finder. Combine, in any direction:

- environmental ranges — depth, salinity, temperature, sea-surface temperature
- a geographic bounding box
- organism groups, taxonomic ranks, specific species, free-text / minimum reads

Results render as a ranked species bar (click to pin a species as a filter), a
detection map, a depth-vs-salinity environmental scatter, a per-species
environmental envelope (min–median–max), and a sortable species table. The
scatter's **X / Y / size** selectors now expose every numeric column present in
the detections, not just the environmental ones.

## Universal table & chart tools (`js/enhance.js`)

Every chart/table card gains a small toolbar that appears in the **top-right
corner on hover** and disappears when you move away:

- **⤓ Export** opens a popup:
  - *Charts* → PNG / JPEG / SVG / PDF / HTML, with a **DPI** (and optional pixel
    width) control for raster formats. Raster scale = DPI ÷ 96.
  - *Tables* → CSV / XLSX / HTML. Exports respect the current sort order and any
    hidden / derived columns (i.e. it exports *what you see*).
- **⚙ Columns / edit** (tables) lets you **hide / show columns** and **add
  derived columns** from a formula over the other columns (e.g. `reads / samples`,
  or `col("Total Reads") / col("Samples")`).
- **Sort** — every table is sortable by clicking a header (ascending ⇄
  descending). Tables already wired to the app's own sort keep it; the rest are
  made sortable by this layer.

Per-table hidden/derived-column choices persist in the browser (`localStorage`).
The layer is framework-agnostic and re-applies itself after Vue re-renders.

XLSX export uses SheetJS and PDF export uses jsPDF, both loaded from cdnjs
alongside the existing Vue / D3 / Leaflet CDN scripts.

## Custom SQL tab

The **🛢 SQL** tab is a read-only query console for trusted analysts (Postgres
sources only):

- A SQL editor (run with the button or **Ctrl/Cmd+Enter**) with a row-limit
  control and a browsable list of tables / columns (click to insert).
- **Saved queries** are kept in the browser (`localStorage`).
- Results show as a sortable table **and** a *Quick chart* view whose bar /
  scatter / line **X and Y axes** can be set to any result column.

The backend (`POST /api/sql/query`) accepts a **single `SELECT` / `WITH`
statement only** — it strips comments, rejects multiple statements and any
mutating / DDL keywords (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `COPY`,
…), runs on a read-only session with a `statement_timeout`, and caps the result
with an outer `LIMIT`. Caps are tunable via `SQL_MAX_ROWS` / `SQL_TIMEOUT_MS`.

## Running the API

```bash
bash api/run.sh
```

This creates `api/venv`, installs `api/requirements.txt`, copies
`api/.env.example` to `api/.env` on first run and starts Flask on
`http://127.0.0.1:5050`. Edit `api/.env` for your Postgres credentials, or just
use the bundled example workbook / add an Excel or Google Sheets source from the UI.

| Variable | Default | Purpose |
|---|---|---|
| `PGHOST` `PGPORT` `PGDATABASE` `PGUSER` `PGPASSWORD` | `127.0.0.1` `5432` `postgres` `postgres` — | default Postgres source |
| `API_HOST` / `API_PORT` | `127.0.0.1` / `5050` | listen address (use `0.0.0.0` only behind a proxy/firewall) |
| `FLASK_DEBUG` | `0` | never enable on a shared network |
| `CORS_ORIGINS` | — | extra allowed browser origins, comma-separated |
| `TAXDUMP_DIR` | `taxdump` | NCBI `names.dmp` + `nodes.dmp` for lineage endpoints |
| `MBON_CONNECTIONS_FILE` / `MBON_IMPORTS_FILE` | `connections.json` / `imports.json` | server-side stores (git-ignored) |
| `LOG_LEVEL` / `LOG_FILE` | `INFO` / `logs/api.log` | logging (`LOG_FILE=-` disables the file) |
| `SQL_MAX_ROWS` / `SQL_TIMEOUT_MS` / `MAX_CONTENT_MB` | `5000` / `15000` / `64` | safety limits |

Errors are returned as JSON (`{"error", "detail"}`): bad query parameters give
`400`, an unreachable database `503`, and unexpected failures `500` with the
traceback in the log. Every request is logged (warnings for 4xx/5xx).

On a fresh checkout `api/connections.json` is created with two sources: the
Postgres profile from the `PG*` variables and **Example data (synthetic
workbook)** (`data/example/dashboard_example.xlsx`). The example source is active
unless `PGHOST` is set.

## Running the dashboard

```bash
bash frontend/make-config.sh            # writes frontend/config.js from API_URL
python3 -m http.server 8280 -d frontend
```

Open <http://localhost:8280>. `API_URL` is taken from the environment, `api/.env`
or the repo-root `.env` (default `http://127.0.0.1:5050/api`). Without
`config.js` the app falls back to that default. `frontend/metadata.html` is a
standalone page (no API needed) that starts with built-in demo data and accepts
dropped `.xlsx` / `.csv` files.

`deploy/` contains systemd units (replace `REPO_DIR` / `USER`) and a docker
compose file for a local Postgres (+ optional Metabase: `--profile metabase`).

## CI

`.github/workflows/ci.yml` runs on pushes and pull requests:

- **lint** — `flake8` (syntax errors + undefined names) and `node --check` on the JS
- **test** — `pytest` (pipeline, ingest validation, API adapters)
- **example** — validates and builds the example report and uploads it as an artifact

## API quick reference

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | API + database status |
| `GET /api/connections` | list data sources (secrets masked) |
| `POST /api/connections` | add a source `{name,kind,config}` |
| `POST /api/connections/<id>/activate` | switch the active source |
| `POST /api/connections/<id>/test` | test connectivity / sheet detection |
| `GET /api/explore/schema` | env ranges, groups, ranks, bbox for the active source |
| `GET/POST /api/explore/query` | env-range + species cross-filter |
| `POST /api/sql/query` | run a single read-only `SELECT` `{sql,limit}` (Postgres only) |
| `GET /api/sql/tables` | list tables + columns of the active Postgres source |
| `GET/POST/DELETE /api/import` | browser-side import store |

`/api/explore/query` accepts `depth_min/max`, `salinity_min/max`,
`temp_min/max`, `sst_min/max`, bbox (`s,n,w,e`), `groups`, `ranks`, `species`,
`stations`, `search`, `min_reads`, `top` (CSV in GET, arrays/objects in POST).
