# Input data formats

Both `build_mbon_html.py` and `ingest.py` read the same, standardized folder
layout. `data/example/projects/` is a complete working example of everything
described here (generated by `make_example_data.py`).

```
data/projects/                      # --projects-dir / EDNA_PROJECTS_DIR
├── report_manifest.xlsx            # the controller (one row per sample or batch)
└── <project_dir>/
    ├── faire/    FAIRe checklist(s): per-sample metadata, coordinates, environment
    ├── kraken2/  Kraken2 reports  — flat, or kraken2/<DATABASE>/<run>/…
    ├── wilder/   Wilderlab ASV workbooks (WLM*.xlsx)
    └── meta/     concordance.json (written by `ingest.py concordance`)
```

## report_manifest.xlsx

First sheet (or a sheet named `Sheet1` / `manifest`); a `.csv` with the same
columns also works. Header matching ignores case, spaces and punctuation, and the
aliases in brackets are accepted.

| Column | Required | Meaning |
|---|---|---|
| `sample_id` [sample, samp_number, samp_name, sid, uid] | **yes** | Sample (or batch) key. For Wilder data this is the `ClientSampleID`; it must match `samp_number` / `samp_name` / `Station` in the FAIRe sheet to get coordinates. |
| `run` | | Run / sequencing batch name. Used by `--runs` / `--skip-runs`. |
| `project` | recommended | Project name — the builder makes one set of runs per project. |
| `project_dir` | | Folder under `data/projects/` (defaults to `project`). |
| `cruise` | | Cruise / collection date (e.g. `20260714`). |
| `metadata` | recommended | FAIRe checklist filename (searched in `faire/`, `meta/`, the project folder, `wilder/`). |
| `k2_report` | | Kraken2 report file **or** folder, relative to `kraken2/` (a `<DATABASE>/` level is searched automatically). Several allowed, `;` or `,` separated. |
| `asv_report` | | Wilder workbook(s) in `wilder/`; the `.xlsx` extension may be omitted. |
| `barcodes` | | `TRUE` to expand a folder of `barcodeNN` reports into one sample per barcode, or the filename of a barcoding workbook (tabs with `Sample` + `Barcode` [+ `sample_ID`] columns). |
| `disable` | | `TRUE` / `1` / `yes` / `x` skips the row everywhere. |
| `platform` | | Sequencing platform (Illumina, Oxford Nanopore, …). |
| `sample_type` | | Optional override: `SAMPLE`, `POSITIVE_CONTROL`, `NEGATIVE_CONTROL`, `OTHER`. |

Any other columns are carried into the report as per-sample metadata.

## FAIRe checklist (`faire/*.xlsx`)

A `sampleMetadata` sheet. The header row is detected automatically (FAIRe
templates put requirement-level and section rows above it). Recognised columns:

* key: `samp_number` (preferred) or `sample_ID`; also `samp_name`, `materialSampleID`, `Station`
* location: `decimalLatitude`, `decimalLongitude` (decimal degrees; swapped values are
  repaired, `0,0` and out-of-range values are ignored), `geo_loc_name`
* environment (shown on the map and in Explore): `temp`, `salinity`, `Sample Depth`,
  `minimumDepthInMeters`, `maximumDepthInMeters`, `samp_category`,
  `samp_collect_device`, `samp_store_sol`, `eventDate`
* controls: `neg_cont_type`, `pos_cont_type` (`not applicable` etc. are treated as empty)

If a `samplesheet_v1` sheet is present (OceanX-style checklists), its
`sample_ID` / coordinates override blank coordinates in `sampleMetadata`.

## Wilderlab ASV workbook (`wilder/WLM*.xlsx`)

| Sheet | Content |
|---|---|
| `metadata` | `Key:` / value rows (JobID, AccountName, …), then a table with **`UID`**, **`ClientSampleID`**, `Latitude`, `Longitude`, `CollectionDate`, … |
| `aggregated` | **`ScientificName`**, **`Rank`**, `TaxID`, `CommonName`, `Group`, then one read-count column per sample `UID`. A two-row header with merged labels is also handled. |
| `full` | optional: one row per ASV with `Sequence`, `Target` (assay) — used for the assay labels. |

Only `Rank == species` rows are plotted. UID columns are linked to samples through
`metadata` (`UID → ClientSampleID`) or, failing that, `meta/concordance.json`.

The older **Wilder_02** export (separate `WilderlabSamples*.csv` + `WilderlabTaxa*.csv`
[+ a detections table with `SID`, `TaxID`, reads]) is read with
`--include-unmanifested --include-wilder02`.

## Kraken2 reports (`kraken2/…`)

Standard Kraken2 `--report` output, one file per sample, tab-separated:

```
pct  clade_reads  direct_reads  rank  taxid  indented_name
```

The 8-column `--report-minimizer-data` variant is also accepted. Recognised
extensions: `.kraken2.report.txt`, `.kraken2.report`, `.kraken.report`, `.kreport`,
`.k2report`, `.report`. Species (`S`) rows are used; if a report has no species-level
reads the finest populated rank is used instead and labelled, e.g. `Vibrio (genus)`.
Names like `Tursiops truncatus (bottlenose dolphin)` are split into scientific and
common name. Lines starting with `#` and malformed lines are ignored (and counted
in the debug log).

Database folders: `kraken2/<DATABASE>/<run>/<sample>.kraken2.report.txt` keeps
results from different reference databases apart; the report gets a Database
selector. Demultiplexed Nanopore runs can use `<run>/<run>__barcode07/…` folders or
flat `barcode07-*.report` files together with the manifest `barcodes` column.

## meta/concordance.json

Written by `python ingest.py concordance --all`. Maps every Kraken2 report path and
Wilder `job:UID` to a FAIRe sample key; anything that could not be matched is listed
under `"unmatched"` so you can fix names and re-run. The builder uses it when a
manifest row names a whole folder of reports.

## Report payload JSON

`build_mbon_html.py --json-out file.json` saves the exact data embedded in the HTML,
and `--from-json file.json` renders it again (e.g. after editing titles or merging
payloads in another tool). Top-level keys: `title`, `isExample`, `generatedAt`,
`map {center, zoom}`, and `runs[]` — each with `id`, `label`, `kind`
(`kraken2` / `manifest` / `Wilder_01` …), `stations[]`, `samples[]`, `taxa[]`,
`meta{}`, `sources[]`, `warning`. See `examples/example_payload.json`.
